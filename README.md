### `gen-android` — Scaffold Android projects from a template

A single-binary CLI that generates a new Android or Kotlin Multiplatform project from an embedded template — no git clone, no network.

```bash
gen-android <package.name> <ProjectName> [flags]
```

**Examples:**

```bash
gen-android com.example.myapp MyApp                          # multi-module template
gen-android com.example.myapp MyApp -t single               # single-module template
gen-android com.example.myapp MyApp -t empty                # minimal Compose app
gen-android com.acme.notes AcmeNotes --app-name "Acme Notes" --min-sdk 26
gen-android com.example.myapp MyApp --template kmm --team-id ABCDE12345
gen-android com.example.myapp MyApp -o ~/projects --no-git
gen-android com.example.myapp MyApp --icon logo.svg --icon-bg "#1E88E5"
gen-android icon logo.svg --dir MyApp --bg "#1E88E5"   # update an existing project
gen-android --list
```

The `gen-android` binary embeds the project templates at compile time via Go's `//go:embed`. It extracts the files into `<output>/ProjectName/`, rewrites package and project names in all paths and source files, and runs `git init` with an initial commit.

**Flags:**

| Flag               | Description                                              |
| ------------------ | -------------------------------------------------------- |
| `-t`, `--template <name>` | Template to use: `main` (default), `single`, `empty`, `kmm` |
| `-o`, `--output <dir>` | Parent directory for the new project (default `.`)       |
| `--app-name <name>` | Name shown under the app icon, spaces allowed (default: ProjectName). Sets Android `app_name`, iOS `CFBundleDisplayName` and the desktop window title |
| `--min-sdk <n>`    | Android minSdk, 23–36 (default per template, shown by `--list`) |
| `--team-id <id>`   | Apple team ID written to the iOS config (`kmm` template only)   |
| `--no-git`         | Skip `git init` and the initial commit                   |
| `--icon <file.svg>`| Generate the launcher icon from an SVG                   |
| `--icon-bg <color>`| Launcher icon background, `#RGB` or `#RRGGBB` (default white) |
| `--list`           | List available templates                                 |
| `--version`        | Print the gen-android version                            |

Flags may appear before or after the positional arguments. The package name must have at least two lowercase segments and no Kotlin keywords; the project name must be letters and digits only.

**Launcher icon:**

`--icon` (or the `icon` subcommand on an existing project) renders the SVG with a pure-Go rasterizer and writes:

- `mipmap-*dpi/ic_launcher.png` and `ic_launcher_round.png` (legacy, 48dp)
- `mipmap-*dpi/ic_launcher_foreground.png` (adaptive, 108dp), also used as the themed-icon (monochrome) layer
- `values/ic_launcher_background.xml` with the background color
- `iosApp/.../AppIcon.appiconset/app-icon-1024.png` (opaque) for KMM projects

Existing `ic_launcher*` mipmaps and drawables are replaced. By default the artwork fills the adaptive safe zone (66 of 108dp); adjust with `icon --scale 0.5`. Text, images, masks, clip paths, filters and patterns aren't supported — convert them to paths first (Inkscape: *Object to Path*).

**Install:**

```bash
go install github.com/paulcoding810/android-template@latest
```

Or build from source:

```bash
git clone https://github.com/paulcoding810/android-template
cd android-template
make build
```

`make build` deletes local build output (`build/`, `.gradle/`, `.idea/`, `local.properties`, …) from the template folders first, because `go:embed` cannot exclude paths and would otherwise bloat the binary. The generator also skips these paths when writing a project.

Generated projects start `gradle.properties` with `# Generated by gen-android <version> (<template> template)`, so you can tell which template version a project came from.

**Release:**

```bash
git tag v0.1.0 && git push origin v0.1.0   # go install …@latest then reports v0.1.0
```

`make build` stamps the binary with `git describe --tags --dirty`; `go install` uses the module version. Tags are permanent once the Go module proxy has fetched them, so don't move or reuse one.

**Repository layout:**

```
main.go                 entry point, calls internal/cli
internal/cli/           flag parsing, create and icon commands
internal/generate/      template extraction, renaming, validation, git init
internal/icon/          SVG to Android/iOS launcher icons
internal/version/       build version (ldflags, go install, or VCS revision)
templates/              embedded project templates (embed.go lists them)
scripts/                maintenance scripts (upstream-diff)
```

To add a template, put the project under `templates/<name>/` (using package `com.paulcoding.androidtemplate`, name `AndroidTemplate`, and `Android Template` wherever the user-visible app name goes), define minSdk once as `android-minSdk` in `gradle/libs.versions.toml` (modules read `libs.versions.android.minSdk`), and add it to the `go:embed` line and `All` in `templates/embed.go`. `--template` and `--list` pick it up from `All`.

**Develop:**

```bash
make test   # generates every template into a temp dir and checks renaming
```

**Keep templates current:**

```bash
make upstream-diff                          # compare templates/single with `android create`
make upstream-diff TEMPLATE=templates/main
```

Generates a fresh project with the [Android CLI](https://developer.android.com/tools), lists library and plugin versions that differ (matched by Maven coordinate), then diffs the build config files. Requires the `android` CLI and Python 3.11+. The KMM template should be compared against the Kotlin Multiplatform wizard instead.

### What's inside

| `--template`        | minSdk | Contents                                              |
| ------------------- | ------ | ----------------------------------------------------- |
| `main` (default)    | 25     | Multi-module Android app: `app`, `core/*`, `feature/*` |
| `single`            | 25     | Single-module Android app: `app/`                     |
| `empty`             | 24     | Minimal Compose app: one screen, no Ktor/Koin/Room/navigation. Build config follows `android create empty-activity` |
| `kmm`               | 29     | Kotlin Multiplatform: `shared`, `androidApp`, `iosApp`, `jvmApp` |

All templates use Kotlin, Jetpack Compose (Compose Multiplatform for KMM), Gradle Kotlin DSL and proguard rules.
